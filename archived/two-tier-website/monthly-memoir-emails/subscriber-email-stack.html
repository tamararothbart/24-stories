Monthly Memoir — Complete Subscriber Email Stack

Scroll through from top to bottom. Every email a Monthly Memoir subscriber receives, in the order they receive it. Emails that don't apply are marked clearly so you keep your place in the sequence.

How the build works

One Airtable. One Subscribers table. There is no separate table or base for Monthly Memoir subscribers. Everyone is in the same Subscribers table — what separates them is a single field: SubscriberTier which is either monthly_memoir or bound_edition.

Two separate PayFast webhook endpoints. When a Bound Edition subscriber pays, PayFast sends the IPN to payfast-webhook.js. When a Monthly Memoir subscriber pays, PayFast sends the IPN to payfast-webhook-monthly.js. This is controlled by which notify_url is set at checkout. The two subscriber flows are naturally separated at the payment stage.

The sending functions check SubscriberTier. The scheduled functions — send-weekly-prompts.js, send-day4-reminder.js, book-onboarding-reminder.js, send-story-queue.js, approve-story.js — loop through Active subscribers and send emails. Currently they treat everyone the same (all subscribers get Bound Edition emails). The Prompt 7 work is to make each function check SubscriberTier and route to the correct email template for each tier.

Nothing changes for Bound Edition subscribers. The existing Bound Edition email flow is completely untouched. Monthly Memoir email variants are added alongside, not replacing anything.

Status of each email: ✅ LIVE = already firing. 🟡 PENDING = template written here but function not yet updated. 🔵 SAME = identical to Bound Edition, no changes needed. 🟣 NEW = no Bound Edition equivalent.
