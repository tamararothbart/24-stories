Current System Overview

The 24 Stories backend is built on three platforms: Make (automation), Airtable (database), and Mailjet (email delivery). Stories are captured via a custom HTML page (tell.html) hosted on Netlify. The automation is organised into five named scenarios, of which one is fully working, one is working but incomplete, one has errors, one is broken, and one is partially built.

Critical operating note

All 5 Make scenarios auto-deactivate when they hit errors. After every session, confirm all toggles are ON. In each scenario's settings, set Max consecutive errors to 10 to prevent auto-deactivation during testing.

Airtable base name: "52stories" (old name — this is the correct base. Do not rename it. All 5 scenarios reference it.)

Sender email: stories@24stories.co.za (verified in Mailjet, SPF and DKIM confirmed working)

Field naming convention: All webhook fields use PascalCase — e.g. StorytellerEmail, FamilyEmails. This is critical. Lowercase mismatches break Make modules silently.

Scenario 2 — Story Submission

Partial — Incomplete
tell.html Webhook → HTTP (Claude API clean) → Airtable Save Story → Email to stories@24stories.co.za

What it does

When a storyteller submits a story via tell.html, the transcript is sent to Make via webhook. Make passes it to the Claude API for light cleaning (spelling, punctuation — voice preserved). The cleaned story is saved to the Airtable Stories table. A copy is emailed to stories@24stories.co.za for review before family distribution.

Scenario 3 — Family Email Delivery

Has Errors
Airtable Watch Record → Airtable Get Record → Mailjet ×10 recipients

What it does

When an Airtable Stories record is updated (story approved/saved), Scenario 3 watches for the change, retrieves the full Subscriber record to get the family email list, and sends the story to up to 10 family recipients via Mailjet.

Known issues requiring immediate fix

  • Critical: "Missing value of required parameter 'id'" — the Airtable Get Record module is not receiving the Record ID from the Watch Record module. The Watch Record output must be mapped correctly to the Get Record input ID field.
  • Untested — likely to error: Single-recipient edge case. The Mailjet module has Recipient 1–10 fields using the split formula. If fewer than 10 emails exist, blank recipient slots may cause Mailjet to throw a validation error. Must be tested by submitting a story with only one family recipient. Fix: add an ifempty or conditional filter in Make to skip blank recipient fields.

Pending additions (pre-launch)

  • Add the story text to the family email body — confirm it is rendering correctly with line breaks.
  • Add a "Suggest a story for [storyteller name]" link in the footer of every family delivery email. This link points to suggest.html?id={{subscriber_record_id}}. The family member sees this opportunity every time a story arrives — up to 24 times over six months.

Stage C — Audio Upload at Story Submission

C1 Update tell.html — upload audio to Cloudinary before webhook fires

Currently tell.html sends only the text transcript to Make. Update the JavaScript submission flow as follows:

  1. When the storyteller presses Send, capture the audio blob (already recorded).
  2. Upload the audio blob to Cloudinary using an unsigned upload preset (create one in Cloudinary Settings → Upload Presets → Unsigned). The upload goes to the /24stories/stories/audio/ folder.
  3. Cloudinary returns a JSON response containing the secure_url of the uploaded file.
  4. Include that URL as AudioURL in the Make webhook payload, alongside the existing transcript and subscriber ID fields.

The storyteller sees no difference — the upload happens in the background between pressing Send and the confirmation message appearing.

Note on audio format

Browser voice recordings are typically audio/webm or audio/ogg. Cloudinary accepts both. For maximum compatibility in the book QR code (played on any device), convert to MP3 on upload using Cloudinary's transformation parameter: format: mp3 in the upload options.

Stage F — my-stories.html (Subscriber Personal Archive)

F1 Build my-stories.html — full page build

Accessed via: https://24stories.co.za/my-stories.html?id={{subscriber_record_id}}. No login — link-based access only. Included in every prompt email as "View your stories."

Cover section (top, always visible)

  • Upload cover portrait photograph → uploads to Cloudinary /subscribers/covers/ → returns URL → saves to Airtable Subscribers CoverImageURL
  • Dedication text field (optional) → saves to Airtable Subscribers Dedication
  • Save button for both fields

Story cards (26 cards, in order below cover section)

  • On page load: fetch all story records for this subscriber ID from Airtable. Fetch subscriber record for cover + dedication.
  • Submitted stories: Show prompt text, story text, image upload slot, caption field, Save button. Image upload goes to Cloudinary /stories/images/ → saves ImageURL and Caption to the correct Stories record in Airtable.

  • Subscriber can return and update images and captions at any time — not a one-time window.

Stage G — Legacy Book Template & Compilation

G1 Build the Legacy Book HTML/CSS template

The book is built as a self-contained HTML file styled for print (A4 or 8.5"×11" — confirm preferred size). It pulls all stories and images for a given subscriber from Airtable at generation time.

Book structure (page order)

  1. Cover page: CoverImageURL (full bleed), StorytellerName, a subtitle (e.g. "A Life in 24 Stories"), year.
  2. Dedication page: Dedication text, centred, set in Cormorant Garamond italic.
  3. Table of contents: List of 24 story titles (or first lines) with page numbers.
  4. Story pages (24 pages minimum, one story per page or spread):
    • Chapter number + prompt text (as chapter heading)
    • Story text body
    • If ImageURL: photograph with caption below
    • If AudioURL: QR code image generated from https://api.qrserver.com/v1/create-qr-code/?size=120x120&data={{AudioURL}} with caption: "Scan to hear [StorytellerFirstName] tell this story."
  5. Closing page: Simple colophon — date compiled, 24stories.co.za.

Typography

Cormorant Garamond for headings and chapter titles. Inter for body text at 11pt. Gold (#B8976A) for chapter numbers and decorative rules. Cream (#F7F5F2) for chapter title backgrounds if desired.

G2 Build book-admin.html — manual trigger page for Tamara

A simple private page (not linked publicly) that Tamara uses to generate a book for any subscriber. The page has one field: Subscriber Record ID (or a dropdown of subscriber names fetched from Airtable). On clicking "Generate Book," it opens or downloads the populated book HTML for that subscriber, ready to print to PDF.

Password-protect this page with a simple hardcoded passphrase in JavaScript — sufficient for beta. Replace with proper auth post-launch.

G3 PDF generation method

The simplest method for beta: browser print-to-PDF. The book HTML is opened in Chrome and printed to PDF using Chrome's built-in print dialog (File → Print → Save as PDF). CSS @page rules and @media print styles control margins, page breaks, and print formatting. This requires no server, no additional software, and produces high-quality output from Chrome.

For automated generation at scale (post-launch): Puppeteer (headless Chrome via Node.js) can be run as a Netlify serverless function, called from book-admin.html, and returns the PDF as a download. This is a post-launch build — document it but do not build it yet.

Print settings for beta

Chrome → Print → Destination: Save as PDF → Paper size: A4 → Margins: None → Scale: 100% → Background graphics: On. This produces a print-ready PDF with full bleed cover image.
