Hard Rules — Do Not Violate

  • Do not add fields to Airtable. Any schema change breaks Make module field mappings across every scenario. The schema is locked at v3.2.
  • Do not use Airtable Watch Records as a Make trigger. Confirmed broken in this project. Use scheduled trigger + Search Records, or webhook-triggered.
  • Do not use the Formula field in Airtable Search Records in Make. Make's variable system breaks any formula entered there. Leave it empty. Place filter conditions in Make's native filter module after the Search Records module.
  • Do not insert modules between existing modules. Make does not support this. To change the middle of a chain, rebuild the scenario from scratch.
  • Do not delete or recreate the Stage 2 webhook. The URL https://hook.eu1.make.com/63gxymbozbgic8v4qtvjzn9nkruo3g8k is registered in PayFast as the live notify_url. Rebuild Stage 2 in place.
  • All automated emails send from stories@24stories.co.za only. Never hello@. hello@ is Tamara's manual address.
  • Filter StoryHelperEmail not empty before every Story Helper Mailjet module in every scenario without exception.
  • Iterator Array field: in the Array input, open the variable picker and select "Airtable — Search Records (bundle)" — the single item at the top of the list. Do not select individual field badges.
  • Variables in Mailjet HTML body and subject: insert via the variable picker (blue badges). Do not type curly brace syntax manually — it will not resolve.
  • tell.html cleanup.js uses claude-sonnet-4-6. Do not downgrade to Haiku.
  • Test via Hoppscotch. Make must be in Run Once (listening) mode before sending a test payload. If Make is not listening, the payload is lost and Make does not receive it.
  • Router stays black/grey during execution. This is correct Make behaviour, not an error.
  • DNS — do not touch. SPF, DKIM, MX records on GoDaddy are correctly configured.
