4. Complete Story Submission Flow S4

Critical architecture point: Stories are NEVER submitted directly from library.html. The library links to tell.html with URL params pre-filled. All story submission — whether triggered from the weekly prompt email or from the library "Record this story" button — goes through tell.html and the same Make webhook. Timing of when the subscriber records (promptly, late, or ahead of schedule) is irrelevant to how Make processes the submission.

Path A — Submitted via Prompt Email Link

Make builds a tell.html URL with 6 URL params (id, week, weekname, theme, prompt, angles) and includes it in the weekly prompt email. Storyteller clicks → tell.html loads the prompt from URL params.

Path B — Submitted via Library ("Record this story" button)

library.html reads all 26 prompts from Airtable (Prompts table) and builds the same tell.html URL with the same 6 params. Storyteller clicks the button on any story card — including past, current, or future weeks. Same tell.html, same webhook. No difference in processing.

On tell.html — Two Input Modes

Voice recording mode

1. Subscriber taps Record → browser captures audio via MediaRecorder API
2. On stop: audio uploaded to Cloudinary (cloud: dorv3glde, preset: 24stories, folder: stories/audio). Returns audioURL.
3. Netlify function /.netlify/functions/transcribe called with audioUrl. Function fetches audio from Cloudinary → sends to OpenAI Whisper → gets raw transcript.
4. Transcript sent to Claude Haiku (via Anthropic API). Prompt: fix spelling, apostrophes, capitalisation, punctuation; remove filler words; break into paragraphs. Do not rewrite sentences. Do not add words.
5. Cleaned text returned to browser → appears in editable textarea. Subscriber can review and correct before submitting.

Typed text mode

1. Subscriber types freely. Draft auto-saved to localStorage every 1.5 seconds.
2. Subscriber clicks "Clean up my story" → Netlify function /.netlify/functions/cleanup called with raw text → Claude Haiku applies same mechanical cleanup (spelling, punctuation, filler words, paragraphs — no rewrites). Cleaned text replaces textarea content.

Photo upload (both modes)

Subscriber selects photo → uploaded immediately to Cloudinary (folder: stories/images) → imageURL stored in browser memory. Submitted with story payload. Not required — library can be used to add photo later.

Make Receives Submission — Scenario 6

Make (Scenario 6) receives the webhook payload and:

  1. Looks up the subscriber record in Airtable using subscriberId
  2. Creates or updates a Stories record: StoryText = storyText, StoryImageURL = imageURL, StoryImageCaption = caption, AudioURL = audioURL, SubmissionDate = submittedAt, PromptNumber = weekNumber
  3. Notifies Tamara (alert or Airtable notification) that a story has been submitted and is ready to edit

Tamara Edits — Family Delivery Triggered

Tamara opens the Stories record in Airtable and types her edit into EditedText. Make watches for EditedText to be filled. When it is:

  1. Make sends email 6 (Story Confirmation) → Storyteller only
  2. Make sends email 7 (Story Delivery) → all FamilyEmails
Weekly schedule = Tamara's editorial discipline, not Make automation. The library copy says "Your family receives each story on its weekly schedule." This is maintained by Tamara only filling EditedText on the weekly send day — not by a Make timer. If a subscriber submits week 8 during week 3, Tamara holds the edit and fills EditedText during week 8. Make fires immediately when she does.

5. Story Library (library.html) S5

Purpose

  1. Subscribers can record any story (past, present, or future prompt) without needing the original email link.
  2. Subscribers and Story Helper can upload or update photos and captions at any time.
  3. Subscribers and Tamara review all edited stories and book prep before printing. The library is the proof. No separate client proof step.

Access Model

  • URL-based: library.html?id=[AirtableRecordID] — the Airtable record ID of the subscriber. The URL is the key. No password. No login page.
  • Library link in the footer of every applicable email.
  • "Resend my library link" form on main site — subscriber enters email, Make looks up their record and emails the link. Safety net for core demographic (70+).
  • Three users: Storyteller (their URL), Story Helper (same URL), Tamara (accesses any URL she has in Airtable).
  • Preview mode: library.html?id=PREVIEW — loads mock data without Airtable. For testing only. Remove before go-live.

Prompts — All 26 Unlocked from Day One

Pay-upfront model. No prompt lock logic. Subscriber can record any story at any time. Make still sends weekly prompt emails on schedule — the library does not replace the emails. Family delivery maintained weekly by Tamara's editorial discipline (see Section 4).

Story Cards (26)

Each card shows: week number, WeekName, Theme, prompt text, story status, photo upload, caption (always editable).

Status states (as should be — see bug note above):

  1. Empty — no story submitted. "Record this story" button → links to tell.html with all 6 URL params pre-filled.
  2. Awaiting edit — StoryText filled, EditedText empty. "Your story is being edited. It will appear here soon."
  3. Edited — EditedText filled. Shows the edited story text. Read-only.

Story Editing Rules

  • EditedText is read-only in the library. Only Tamara edits, via Airtable.
  • Factual corrections: subscriber emails hello@. Tamara edits Airtable. Library updates on next load. Not promoted — quiet fallback only.

Book Preparation Section (bottom of library)

  1. Book title — editable. Default pre-populated: "The Collected Stories of [StorytellerFirstName] [StorytellerSurname]". Saved to Subscribers.BookTitle via HOOK_BOOK_TEXT. Only written if subscriber edits it.
  2. Portrait photo — inside cover page only. Used as front cover only if no cover image provided.
  3. Cover image — optional. Front cover. If absent, portrait is used as fallback.
  4. Dedication — editable text field. Saved to Subscribers.DedicationText.
  5. Delivery address — required for Courier Guy. Saved to Subscribers.DeliveryAddress.
  6. Delivery phone — mobile number for courier. Saved to Subscribers.DeliveryPhone.
  7. Book summary — written by Tamara at week 26, custom per subscriber. Entered in Airtable (Subscribers.BookSummary). Read-only in library.
Cover logic (locked): Portrait = inside cover page. Cover image = front cover (portrait as fallback). These are separate. Do not describe them as interchangeable in copy or UI.

Mark as Complete

  • Sets BookFormCompleted date in Airtable → triggers Make to alert Tamara
  • Locks the library: no further changes can be made
  • Starts the delivery clock (allow up to 3 weeks from print dispatch to door)

Warning modal before pressing: "Once you mark your library as complete, your book goes straight to production. No further stories, photographs, or changes can be added. Your delivery window begins from this moment." Requires explicit confirmation.

Technical Architecture

  • Config vars in library.html (replace before go-live): AIRTABLE_KEY, AIRTABLE_BASE, HOOK_STORY_PHOTO, HOOK_CAPTION, HOOK_BOOK_PHOTO, HOOK_BOOK_TEXT
  • Reads: Airtable API direct from browser (read-only key). Fetches Subscribers record + Stories records (filtered by SubscriberRecordID formula) + all 26 Prompts records (sorted by Week field — see note below).
  • Writes: Cloudinary → Make webhooks (4 separate hooks). No direct Airtable writes from browser.

12. Policies S12

Refund

Non-refundable. Disclosed at checkout with explicit checkbox. Exceptional refunds only — manual, Tamara from hello@. Email 16 sent only on manual exceptional refunds.

Pause

  • One pause allowed. Up to 12 months from subscription start date.
  • Subscriber emails hello@ to request. Tamara sets PauseStartDate, ticks IsPaused. Make stops prompts.
  • During pause: prompts stop. Library remains accessible.
  • To resume: subscriber emails hello@. Tamara unticks IsPaused, ticks IsResumed. Make restarts from correct week.
  • Email 15 sent by Tamara after processing. Fill [PauseExpiryDate] before sending. Key line: "Your pause is valid until [PauseExpiryDate] — after that point, we will be in touch to check in."
  • Scenario 13 sends subscriber an expiry reminder as 12-month limit approaches.
  • Scenario 13 also alerts stories@24stories.co.za when IsPaused or IsResumed is ticked (spec to be confirmed before build).

Story Corrections

Stories read-only for subscribers. Corrections via hello@. Tamara edits Airtable. Library updates on next load. Not promoted — quiet fallback.
